---
description: Preview and switch the theme (statusline palette + input-bar color + base)
---

The `/theme` command controls three coordinated layers, all driven from
`~/.claude/statusline.ps1`:

- **palette** — the statusline color gradient (`$palette`, keys in `$palettes`)
- **bar** — the Claude Code input-bar (prompt border) color (`$barOverride`)
- **base** — the Claude Code base theme: dark / light / dark-daltonized /
  light-daltonized / dark-ansi / light-ansi / auto (`$baseOverride`)

Model: a **palette is the master selection**. It sets the statusline gradient
and, by default, the bar (its mid-stop color) and base. Each of bar and base can
be overridden independently. Picking a new palette **resets** unpinned overrides
back to the palette's coordinated values; a **pinned** override survives palette
switches, as does anything captured via `/theme save`.

State lives in `statusline.ps1`: `$palette`, `$barOverride`/`$barPinned`,
`$baseOverride`/`$basePinned`, and the `$palettes` / `$paletteBars` / `$paletteBases`
tables. A palette's default bar is its `$paletteBars` entry if present, else its
mid-stop hue.
The active CC theme file `~/.claude/themes/cc-active.json` is regenerated by
running the script with `-Apply`; `settings.json` points `theme` at
`custom:cc-active` permanently, so you never edit `settings.json` here.

Use `powershell.exe` if `pwsh` is unavailable. The apply/preview invocations:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\statusline.ps1" -Preview
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\statusline.ps1" -Apply
```

Parse `$ARGUMENTS` (below) and act:

**No arguments** — run `-Preview` (gallery + active palette/bar/base footer),
then list the palette names and remind the user of the sub-verbs.

**`<palette>`** (a bare name, e.g. `ocean`) — switch palette.
1. Validate the name exists as a key in `$palettes`; if not, list valid names and stop.
2. Edit `$palette = '...'` to the new name.
3. For each layer NOT pinned, clear its override: if `$barPinned` is `$false`,
   set `$barOverride = ''`; if `$basePinned` is `$false`, set `$baseOverride = ''`.
4. Run `-Apply`. Confirm the change and note the statusline refreshes on next render
   and the input bar updates after a Claude Code restart.

**`bar <color>` [`--pin`]** — override just the input-bar color.
- `<color>` must be `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)`, or `ansi:<name>`.
  Reject anything else and stop.
- Set `$barOverride = '<color>'`. Set `$barPinned = $true` if `--pin` was given, else `$false`.
- Run `-Apply`.

**`bar reset`** — set `$barOverride = ''` and `$barPinned = $false`, then `-Apply`
(bar follows the palette again).

**`base <name>` [`--pin`]** — override just the base theme.
- `<name>` must be one of the seven built-ins listed above. Reject otherwise.
- Set `$baseOverride = '<name>'`. Set `$basePinned = $true` if `--pin`, else `$false`.
- Run `-Apply`.

**`base reset`** — set `$baseOverride = ''` and `$basePinned = $false`, then `-Apply`.

**`save <name>`** — capture the current effective look as a new named palette so
it survives future switches.
1. Reject `<name>` if it already exists in `$palettes` (avoid clobbering).
2. Add an entry to `$palettes` copying the current `$palette`'s gradient stops.
3. If the current effective base differs from `'dark'`, add `'<name>' = '<base>'`
   to `$paletteBases`.
4. To bake a specific bar color into the new palette, add a `'<name>' = '<hex>'`
   entry to the `$paletteBars` table (using the current effective bar). Otherwise
   the new palette's bar defaults to its mid stop.
5. Switch `$palette` to `<name>`, clear unpinned overrides, run `-Apply`, confirm.

After any edit, briefly state: which layer(s) changed, the resulting palette/bar/base,
and that the bar change needs a Claude Code restart while the statusline refreshes live.

Arguments: $ARGUMENTS

# Migrate mode

Shared by Beat 1 of the full first-run AND by standalone `/tutorial migrate`.

The whole mode is a router on ONE question. Ask it, wait, then run exactly one route. Respect the
exit/opt-out rule from `SKILL.md` at every prompt.

## The question
Ask, plainly:
> "Before this, how were you using Claude? (a) I'm brand new to Claude Code, (b) I was using the VS
> Code or JetBrains extension on THIS machine, or (c) I had Claude set up on a DIFFERENT machine."

Route on the answer. If unsure which, ask the one disambiguator: "same machine, or a different one?"

## Route A — Brand new / fresh
Nothing to migrate. Say so in one line — "Nothing to bring over, you're starting clean" — and go
straight to Beat 2 (or END if this is standalone `/tutorial migrate`).

## Route B — Same machine, different surface (this is a REVEAL, not a transfer)
Lead with the reframe, because it removes a false worry:
> "Good news: there's nothing to move. The terminal and the VS Code/JetBrains extensions all read
> the same `~/.claude` on this machine, so your history, memory, settings, and skills are already
> right here — they were never separate."

Then, one at a time:
1. Have them confirm it live: run `claude --resume` in the terminal and pick a past conversation —
   including one they started in the VS Code extension. Point out it's the same history.
2. Say what the kit ADDED on top: the skills, hooks, and statusline they just installed.
3. State the honest caveat so nothing looks broken: the **statusline** and **custom keybindings**
   are terminal-only and will NOT render inside the IDE panel. That is expected, not a failure.
4. Only if relevant: if they set `CLAUDE_CONFIG_DIR`, it must be set the same in every surface, or
   they will see different sessions and settings. If they never set it, ignore this.

Then continue to Beat 2 (or END if standalone).

## Route C — Different machine (the REAL transfer)
Be explicit that the tutorial cannot reach the other machine — the user performs the copy
out-of-band. Correctness note to state: `~/.claude.json` lives at the home ROOT (a sibling of
`~/.claude/`), so copying the `~/.claude/` FOLDER already leaves it behind; the only things to
exclude inside the folder are `daemon/` and `ide/` (machine/runtime state that re-login rebuilds).

Walk them through it:
1. **On the OLD machine**, copy `~/.claude` to portable media or a synced folder, excluding the
   runtime dirs. Offer this ready command (PowerShell):
   ```powershell
   robocopy "$env:USERPROFILE\.claude" "D:\claude-backup\.claude" /E /XD daemon ide
   ```
   (Swap `D:\claude-backup` for their USB/synced path.) This carries the parts they want — settings,
   skills, commands, hooks, agents, keybindings, themes, and the kit's own stores `threads/`,
   `goals/`, `session-notes/`, plus per-project `memory/` — and drops only the machine-specific state.
2. **On THIS machine**, copy that `.claude` content into `%USERPROFILE%\.claude` (merging with
   what's here). If prompted to overwrite, keep their real data.
3. **Re-authenticate** here: launch `claude` and log in. This regenerates `~/.claude.json` (auth +
   trust + session state) fresh for this machine — which is exactly why it was not copied.
4. **Run the kit installer** (merge-safe) so the kit's skills/hooks/statusline fold in without
   clobbering anything they just brought over.

Then continue to Beat 2 (or END if standalone).

**Unhappy path (common):** if they're already ON the new machine and the old `~/.claude` is NOT
reachable right now, say so plainly and fall back to Route A — treat them as a fresh start rather
than pretend a no-op migration succeeded. Tell them they can re-run `/tutorial migrate` later once
the old data is accessible.

## Verified facts backing this mode (source: code.claude.com, 2026-07-01)
- Same machine: CLI + IDE extensions share one `~/.claude` (settings, skills, commands, hooks,
  memory, `projects/` transcripts, `history.jsonl`). Continue a VS Code conversation in the terminal
  with `claude --resume`.
- Surface-specific, won't carry: `statusLine`, `keybindings.json`, IDE-only extension toggles.
- `~/.claude.json` is at the home root, not inside `~/.claude/`; it holds auth/trust/session state
  and is regenerated by re-login, so it is never copied. `daemon/` and `ide/` are runtime state.

✦ The day

A two-door model, and getting the doors straight is most of the value. /goals is the standing view: areas of concern that persist for weeks. /today is one day's plan, drawn from those areas. Threads (Memory) are separate from both — they are what happened, not what you intend.

Which door The single most common confusion in the kit.

/goals — the AREAS door

  • Lasts weeks. Survives any single day.
  • "What am I responsible for."
  • Store: goals/goals.md

/today — the DAY door

  • Lasts until tonight. Rebuilt each morning.
  • "What am I doing right now."
  • Store: accountability/today.md

They connect one way

  • Today's picks come from areas.
  • Ticking in /today writes back to the area task.
  • You never sync them by hand.

/goals

Standing areas and their task lists. Bare /goals is also the status board.

/goals
The board: areas, tasks, live counts, today's summary, open thread pointers, drift footer.
/goals new "title"
Define an area, through a short capped interview.
/goals review
Weekly keep / done / drop sweep, with rollover.
/goals done <id>
Tick a task in its area.
/goals link <area> <thread>
Connect an area to the thread doing the work.
/goals plan
Day-planning coach. Every style ends by handing off to /today.
/goals week | long | all
Board scopes.
/goals dump
Sort a pile of unsorted thoughts into areas.

What an area is

A tag, an optional north-star, and its own task list. Deliberately coarse: if you have twenty areas you have a task list, not areas.

The board absorbed the status report

There is no separate "what's my status" command. Bare /goals is that.

Planning styles

guided walks you through it; brainstorm opens it up; dump takes a mess and sorts it; propose has Claude draft a day for you to react to; yesterday starts from what you did last.

All five end by handing to /today. Planning that doesn't produce a day is just more planning.

Not for

Today's plan or ticking today's items — that is /today. Capturing what happened — that is /log. Areas are intent; threads are history.

/today

Pick and tick the 3-5 things you're actually doing today.

/today
Show the plan.
/today plan
Build today's plan with the coach.
done 3
Tick top-level item 3.
done 3, b
Tick sub-item b under item 3.
add "…"
Append a task mid-day.

3-5 is a target, not a cap

Items carry light / medium / heavy weights against a soft budget of about five points. The budget gives feedback once and then never blocks you. It is a mirror, not a gate.

Numbering

Top-level items take numbers. Sub-items are lettered under their parent, restarting at a each time, and never consume a top-level number. So a parent at 3 with two children is followed by 4, not 6.

Ids shift when you add things, so the list re-renders after any edit — always tick against what is currently shown.

The write-back

Ticking here flips the mapped task in goals.md — but only if the tick finishes the whole task. A ticked slice leaves the parent open, and it asks when that is ambiguous.

Weights are ephemeral

Never persisted. Each morning re-coaches from scratch.

When NOT to

Not for standing areas or long-lived tasks — that is /goals. Not for recording what happened — that is /log. Today’s plan is intent, not history.

The store is the only truth. If you mirror the plan somewhere else (OneNote, a notebook), never treat that mirror as a tick source. Mirrors are output.

/eod typed or scheduled

Synthesize the whole day across every effort, not just one thread.

/eod
Run it now, yourself.
/eod 2026-07-14
Reconstruct a past day.
bootstrap\scripts\setup-eod-schedule.ps1
Install a daily run — a late-afternoon pass and an evening pass.

Claude will not run this for you

It is disable-model-invocation, so asking Claude to "wrap up my day" does not reach it. That is deliberate: a day summary costs real tokens and should be your call.

But a scheduler will

The model restriction is not a scheduling restriction. The kit ships setup-eod-schedule.ps1, which installs Windows tasks running run-eod.ps1 -Scheduled. Opt-in, and worth it if you would otherwise forget.

What consumes it

The digest lands in session-notes/eod-latest.md, which is exactly what /reconcile status reads as its prep sheet. So a scheduled /eod quietly makes reconciling cheaper.

When NOT to

Not a substitute for /log. This synthesizes across efforts; it does not record the reasoning inside one. A day summary with no threads behind it has little to summarize.

/eow you type it

End-of-week roll-up across the week's efforts.

/eow
The week's roll-up. Takes no arguments.

Same model rule

disable-model-invocation, like /eod. Claude cannot reach it.

No scheduler ships

Unlike /eod, there is no shipped setup script for this one — so in practice it only happens when you type it.

When NOT to

Not for a single day — that is /eod. Running it daily produces a roll-up of one day, which is just a worse /eod.

Worth knowing

A week with no /eod digests behind it has thin material to roll up. The dailies are what make the weekly worth reading.

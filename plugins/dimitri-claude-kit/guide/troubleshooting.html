⚠ Fixing things

Organised by what you noticed, not by what caused it — you know the symptom, that is the whole point. Each one names the likely cause and what to actually do.

Two things to try first They fix a surprising share of it.

Restart Claude Code

  • Skills, hooks, and settings load at startup. Anything installed or edited mid-session is not live yet.

Check you ran the installer

  • A plugin cannot deliver the statusline, user settings, or the scaffold. Without install.ps1 those are simply absent.

Still stuck?

  • Ask Claude /kit and describe it. For Claude Code itself rather than this kit, use its own /help.

I typed a command and nothing happened

Almost always: the skill is not loaded yet, or the name is not what you think.

Check, in order

1. Restart Claude Code. A freshly installed or edited skill is not live until then.
2. Confirm the name against the overview — it lists every command that ships.
3. Try /kit <what you wanted> and let it route you.

The likely trap

Some things that look like commands are not. /change-review is an always-on format with nothing to run. /eod and /eow exist but Claude will not invoke them for you — you type them yourself.

Claude ignored my instruction

If you have corrected the same thing twice, the instruction is missing rather than unclear.

Where instructions live

Standing preferences belong in CLAUDE.md, which loads every session. Something you said three sessions ago is not remembered — that is what the file is for.

When it is a skill misbehaving

If a specific command did the wrong thing, fired when it should not have, or missed a case, run /skill-builder and describe what happened. It revises the skill so the fix holds next time, instead of just apologising this time.

The startup banner is empty

Expected on a fresh setup. A real defect if you have threads.

If you are new

Correct behaviour — you have no threads. Run /log new "my-first-thread" and it fills in immediately.

If you have threads

The banner reads threads/INDEX.md, not the thread files. An empty banner with real threads means the index is missing or out of sync. /reconcile sync regenerates it — the index is derived, so this is always safe.

If the banner never appears at all, the hook is not running: check that Git Bash is installed, since the hooks need it.

I checked something off and it came back

The two stores are deliberately separate, and a tick in one is not automatically a tick in the other.

The usual cause

You finished a slice, not the whole task. Ticking a day item only closes the underlying area task when it finishes that task outright — otherwise the parent stays open on purpose.

The other cause

The plan was restructured after you ticked. Item numbers are positional, so a rebuild can move what you ticked. Always tick against the freshly rendered list.

To true everything up at once: /reconcile status.

The theme options will not expand

A PowerShell terminal quirk, not a kit problem.

The fix

Click into the command line — the options list — to reveal the choices. They do not expand on their own in PowerShell.

If the theme changes nothing

The integrated colours only take effect with the matching base theme selected. /theme sets that for you on first use; if you had already set a base theme, it keeps yours rather than overriding it.

The day summary never ran

By design: Claude cannot start it. Either you type it, or a scheduler does.

Right now

Type /eod. Asking Claude to "wrap up my day" will not reach it — that restriction is deliberate, since a day summary costs real tokens and should be your call.

Every day, automatically

Run bootstrap\scripts\setup-eod-schedule.ps1 once. It installs an afternoon and an evening pass. A scheduler is not the model, so it is allowed to.

/eow has no shipped scheduler — that one only happens when you type it.

It says my records drifted and I do not know what that means

Two of your files disagree with each other. Nothing is lost, and nothing has been changed without you.

What to do

Run /reconcile sync. It lists what it found in plain language, fixes the derived things itself, and asks before touching anything you wrote.

What it usually is

Harmless bookkeeping: a dashboard row dated behind its thread, a memory file with no index pointer, an auto-capture nobody confirmed. Not data loss.

Not the same as clutter

Drift is records disagreeing. Stale files — dead plans, old drafts — are /deepclean's job, and it proposes before deleting anything.

◌ What runs on its own

Everything on this page happens without you invoking it. If something in Claude spoke to you and you did not ask it to, it is here. Nothing on this page writes to your threads, goals, or day plan — the automatic layer only ever detects and reports.

The short version Three things talk to you. Two things run quietly. Nothing edits your records.

Talks to you

  • Session-start banner — once, when a session opens.
  • Staleness note — mid-conversation, when state moved elsewhere.
  • Statusline — always, at the bottom.

Runs quietly

  • Drift detector — on demand, writes only its own report.
  • Scheduled day summary — only if you opted in.

Never automatic

  • No store is ever written without you.
  • Nothing polls while you are away.
  • Your CLAUDE.md is never overwritten.

The session-start banner

A short summary printed once when a Claude session opens, so you start against real state instead of a blank slate.

Where it gets its content

From threads/INDEX.md — the dashboard your threads generate — plus session-notes/ for the most recent day summary. It reads; it never writes.

Run by session-start-global.sh, through run-bash-hook.cmd so it works regardless of which shell Claude picked.

Why it is sometimes empty

Because you have no threads yet. A fresh install shows a "no threads yet" line instead of a board — that is correct, not broken. It fills in the moment you run /log new.

If it is empty and you do have threads, that is a real problem — see the banner is empty.

The first-run nudge

On a genuinely fresh setup it offers /tutorial once. It stops offering forever once .tutorial-optout exists, which the tutorial creates on request — or you can just ask Claude to disable the prompt.

The staleness note

A one-line note injected into a running conversation when your state changed somewhere else — usually another Claude window.

What makes it fire

Two conditions, checked as you submit a prompt: a store file (threads/, goals.md, INDEX.md, today.md) changed after this session started, or the set of drift findings changed.

The drift half keys on the sorted finding IDs, not the count — so swapping one finding for another at the same count still fires. A count-only check would miss that.

Why it does not repeat

It reports at most once per change-set per session, stamped in staleness-seen.json. So it nags once and then stays quiet until something else actually changes. Silence means nothing changed, not that the check is off.

What it cannot see

It keys off files. Another conversation holding real unlogged work has written nothing, so it moves no file and triggers nothing. Silence from this layer is evidence nothing was written — never that nothing happened.

That gap is exactly why /reconcile sweeps your other sessions directly.

When you see it, re-read the named file before answering anything that depends on it. That is the whole point of the note — a stale answer that sounds confident is worse than no answer.

The drift detector

A deterministic check that compares your records against each other and writes a report. It never fixes anything.

When it runs

On demand, not on a timer. The staleness hook checks the report's age and, if it is older than about ten minutes, spawns one detached detect-drift.ps1 run in the background. So it only ever runs while you are actually using Claude — nothing polls when you are away.

What it writes

Only its own artifacts under janitor/. It reads your stores and writes a JSON report; it modifies no thread, no goal, no plan. Fixing what it finds is /reconcile's job, and that asks you first.

What it finds

Dashboard rows whose dates lag their thread, a snapshot trailing live progress, memory files with no index pointer, goals that have rolled over too many times, unconfirmed auto-captures. Mechanical disagreements — not judgement calls.

The statusline

The line at the bottom of the terminal. Shows where you are working and how much of three budgets you have used.

What the segments mean

working in — the directory in play. Then three filled circles with percentages: 5h and wk are your usage windows, and ctx is how full the current conversation's context is.

ctx climbing past about 80% is the cue to wrap up or start fresh.

Changing how it looks

/theme switches the palette. The kit ships on a neutral default rather than the author's colours.

If it is missing

A statusline cannot be delivered by a plugin — only the installer can set it. If you never ran install.ps1, you will not have one.

Scheduled tasks

Opt-in only. Nothing is scheduled unless you asked for it.

bootstrap\scripts\setup-eod-schedule.ps1
Installs the daily day-summary passes.
bootstrap\scripts\run-eod.ps1
What those tasks actually execute.

What it gives you

A late-afternoon and an evening pass that run the day summary headlessly, so the digest exists whether or not you remembered. The result lands in session-notes/, which is what /reconcile status reads as its prep sheet.

Why this is not a contradiction

/eod is deliberately not model-invocable — Claude will not run it for you mid-conversation. A scheduler is a different thing entirely, and it can. Both statements are true at once.

Removing them

They are ordinary Windows scheduled tasks. Delete them in Task Scheduler, or with schtasks /delete. The install receipt lists what was registered.

Your instructions and your memory

Two things Claude reads every session that are yours, not the kit's.

CLAUDE.md

Your standing instructions, loaded into every session. The kit ships a template, and the installer will not overwrite an existing file — the whole install is merge-safe by rule: back up first, add or merge, never clobber.

Edit it freely. It is the highest-leverage file in the setup.

Memory files

Small files under memory/, one durable fact each, indexed by MEMORY.md which loads every session. Facts, not narrative.

Memory vs threads

A memory is a fact that stays true — a preference, a gotcha, a convention. A thread is the story of one effort over days. If it has a beginning and an end, it is a thread; if it is just true, it is a memory.

● Upkeep

Two different kinds of tidying that get confused constantly, plus the setup commands. Nothing here runs on a schedule you have to remember — reach for these when something feels off, or when the session banner tells you it is.

Records vs files The distinction that keeps these two apart.

/reconcile — the records are wrong

  • Content drift: a task done in reality but open in the store.
  • Edits records. Never deletes files.

/deepclean — the files are stale

  • Superseded plans, dead drafts, past-due leftovers.
  • Deletes and archives. Never rewrites your records.

Both

  • Propose first, act only on your confirmation.
  • Never run headless or unattended.

/reconcile

Make the stores match what actually happened. Two lanes.

/reconcile
Asks which lane you want.
/reconcile sync
Detector-driven: find drift, then fix it.
/reconcile status
Interactive walk-through: tick what you really did, route what never got captured.

The sync lane

A deterministic detector finds mechanical drift — a dashboard row whose date lags its thread, a memory file with no index pointer, a goal that has rolled over too many times. Derived things it just fixes; anything touching your actual content it confirms with you first.

It never hand-edits append-only history. It applies changes by delegating to /log and /goals, so there is one way each store gets written.

The status lane

Walks stations: tick finished thread items, tick finished area tasks, route work that never got captured anywhere, then recap. It reads the /eod digest as its prep sheet rather than re-scanning raw transcripts — so if no digest exists it will ask you to type /eod first, and will say plainly if you skip it.

It sweeps your other conversations

This is the part no file-based check can do. A chat that has real work in it but hasn't logged yet moves no file, so it triggers no drift count and no warning. Silence means nothing was written, never that nothing happened.

So it reads your other recent sessions directly, and if it finds unlogged work it captures it rather than just mentioning it. Anything it couldn't get to gets named as unswept.

When NOT to

Not for deleting stale files — that is /deepclean. This fixes the content of your records and never removes anything from disk. Also not a day summary: it reads /eod’s digest rather than producing one.

It also finds unconfirmed auto-captures. When /log auto guesses which thread your work belonged to, that guess needs a human check. Those markers accumulate invisibly, so the sync lane batches them into one pass for you to confirm or leave open.

/deepclean

The filesystem janitor: delete, move, merge, and archive the stale files /reconcile deliberately never touches.

/deepclean
Takes no arguments. It proposes a full sweep and waits for your confirmation.

What it looks for

Superseded plans, scaffolds already promoted into real code, memory-index drift, dated files that are past due, development leftovers, and docs that have drifted from the code they describe.

How it behaves

Propose then confirm, always. Manual only — never headless, never automatic, never on a timer. It shows you what it wants to remove and waits.

Cadence

Occasional. This is a periodic tidy, not part of any daily loop. Running it monthly is more than enough for most setups.

When NOT to

Not for records that disagree with reality — that is /reconcile. This removes files; it never rewrites a thread or a goal. Reaching for it to fix a wrong checkbox deletes nothing useful and fixes nothing.

/tutorial

Interactive first-run onboarding. Hands-on, on your real data, not a doc to read.

/tutorial
The full first-run walkthrough.
/tutorial migrate
Jump straight to bringing an older Claude setup over.

What it produces

A real, populated thread you will actually keep using — the one where you track how you set up and tweak Claude. It ends with a board that isn't empty, which is what makes the whole save-and-resume loop click.

It goes one step at a time

It waits for you to actually run each command rather than dumping a list. Say "skip" or "I know this" at any prompt and it stops immediately without pushing.

Re-runnable

Run it again any time. If you never want the startup nudge again it will leave an opt-out marker on request.

When NOT to

Not a reference — it teaches the loop once, hands-on. To look something up afterwards use /kit or the guide you are reading. Not for migrating settings on the same machine either; that case is a reveal, not a transfer.

/skill-builder

Build a new skill, or fix one that misbehaved.

/skill-builder
Takes no arguments — say what you want built, or what an existing skill got wrong.

Building

Turn a workflow you repeat into a command. It checks whether something already covers it before starting, which saves you building a duplicate.

Fixing — the underused half

When a skill fired at the wrong moment, missed a case, or did the wrong thing, describe what happened and it revises the skill. That is the difference between an apology and a fix that holds next time.

Reach for it when

You have corrected Claude on the same thing twice. Two corrections means the instruction is missing, not that you were unclear.

When NOT to

Not for using a skill, only for building or fixing one. And not for a one-off task — if you will not repeat it, a skill is overhead.

Worth knowing

It is instant and reversible, which makes it a good first command to try — it confirms slash commands work before anything important depends on them.

/kit

Ask the kit about itself: what exists, which command fits, how two differ.

/kit
The whole inventory, one line per command.
/kit log
Everything about one command.
/kit memory
One layer, with its commands.
/kit stores
A reference section (also ambient, troubleshooting).
/kit "I want to remember what I decided"
Describe the goal in your own words; it routes.

What it does

Reads this guide and answers from it, so there is exactly one copy of the content. Ask about a command, a layer, a topic, or just say what you are trying to do.

When to reach for it

When you half-remember a command, when two of them sound the same, or when you want the answer in the conversation rather than in a browser tab.

When NOT to

For Claude Code's own features, use the built-in /help. For a hands-on first run, /tutorial. To build a skill, /skill-builder.

Worth knowing

Ambiguous words get both answers rather than a guess — ask /kit review and you get /change-review and /scrutinize, with the difference.

It is read-only. Explaining /log never runs it.

It is not called /help on purpose. /help is Claude Code's own, and the baseline door into the tool. A kit that took it over would make things worse for exactly the person most likely to need it.

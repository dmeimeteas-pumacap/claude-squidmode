◆ Memory

Claude starts every session from scratch. These four commands are the only reason your work, decisions, and next steps survive between sessions. A thread is one effort tracked across days — not a to-do list, and not a transcript. If you learn nothing else in the kit, learn /log and /catchup.

How the pieces fit One store, two directions.

Writing

  • /log — you decide what matters, one effort at a time.
  • /logall — catch up on sessions you forgot to log at all.

Reading

  • /catchup — one thread, in depth, with the reasoning.
  • /catchupall — every thread, one line each.

Where it lives

  • ~/.claude/threads/active/ — one markdown file per effort.
  • threads/INDEX.md — the derived dashboard. The thread file always wins.

/log

Capture where an effort stands and why, into a thread.

/log
Capture current state into the thread you're working in.
/log new "title"
Start a new thread. It proposes a name and waits for you to confirm.
/log micro
One line, for something trivial. Skips the reasoning capture entirely.
/log auto
Picks the thread for you and marks the guess unconfirmed.
/log confirm
Clears that unconfirmed marker once you've checked the guess was right.
/log done
Tick off the Next items you've since finished.
/log pause <slug>
Park it. Stays readable, drops off the active board.
/log close <slug>
The effort is finished. Durable conclusions get promoted to memory.
/log merge <a> into <b>
Two threads turned out to be one effort.

What it writes

Each capture records Did (what changed), Thinking (what was uncertain, what you were betting on) and Next (the intended next action). Real decisions additionally get their own entry with the forcing reason, the alternatives you rejected, and how expensive it would be to reverse.

The Thinking half is what makes a cold return work. Outcomes without reasoning read like someone else's notes.

When to reach for it

When you stop, get interrupted, hit a wall, or decide something you'd have to re-derive later. Not on a timer — logging a session where nothing was decided produces noise.

When not to

Pure questions and explanations. Nothing was decided and nothing advanced, so there is nothing to resume.

Worth knowing

Decisions and Log are append-only. A superseded decision gets a new dated entry rather than an edit, so the reasoning chain stays readable.

Where-I-left-off and Next are overwritten every capture. That is intentional and lossless: the previous state is preserved in the Log.

The auto trap. /log auto lets a model guess which thread your work belonged to. Until you run /log confirm, that narrative may be filed under the wrong effort. Those markers pile up quietly — /reconcile now finds them for you.

/catchup

Get briefed on one thread when you return to it. The return trip that makes logging worth doing.

/catchup
No argument: shows the active board numbered, and you pick.
/catchup <slug>
By exact name.
/catchup 3
By row number from the board.
/catchup "that cache thing"
Fuzzy. Searches closed threads too, so old work is recoverable.
/catchup 2026-07-14
Reconstructs a whole day, even from before the thread system existed.
view
Say this after a briefing for the full untrimmed text.

It reads in tiers

A months-old thread would flood the conversation if read whole, so it escalates only as needed: current state first, then the entire decision history for a long gap, then the full log only if you ask. Coming back after weeks? You want the decisions — that is where the why lives.

It is nearly read-only

The one thing it writes is the checkoff prompt at the end, and it does that by handing off to /log done rather than editing anything itself. Capturing fresh state is still /log's job.

It checks other conversations

For a question about state ("what's left", "did we resolve that"), it sweeps your other recent sessions rather than trusting the thread file, because a chat that hasn't logged yet is invisible in it. It will tell you what it swept and what it didn't.

When NOT to

Not for capturing new state — that is /log. Not for a bird’s-eye view of everything at once — that is /catchupall. And not for general questions unrelated to resuming prior work.

/catchupall

Every active thread at once, one line each. The panoramic view.

/catchupall all
The whole board.
/catchupall top 5
Just the first five.
/catchupall 2-6
A range. Also accepts a list like 1,4,9.
/catchupall view all
Print-only dump. Renders full detail verbatim without summarising it.

Use it for

"What do I even have going on." Answering that from memory is how efforts get silently dropped.

Not for

Depth on one thing. Row numbers here match /catchup's, so spot the row you care about and switch.

When to reach for it

When you have lost track of how many efforts are open, or before planning a day, so the picks come from the real board rather than memory.

Worth knowing

Row numbers here match /catchup's, so a row you spot in this view pulls up the same thread there.

/logall

Find every session you never logged and walk them one at a time.

/logall
Walk everything unlogged, interactively.
/logall eod
Sweep today's unlogged sessions, then chain into the day summary.

Why it exists

Logging is a habit, and habits lapse. This recovers the gap instead of losing those days. One session often feeds several threads, which is why it walks them individually rather than filing each one somewhere.

It tracks by session

Coverage is recorded per session id, not per day, so two efforts worked the same afternoon can't hide each other.

When NOT to

Not for a single effort you know you want to record — use /log directly. Reaching for this when one thread is on your mind means walking every unlogged session to get to it.

Worth knowing

Coverage is tracked per session id, not per day, so two efforts worked the same afternoon cannot mask each other.
